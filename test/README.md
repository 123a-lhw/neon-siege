# NEON SIEGE 测试说明

两层互补的自动化测试，都为 **零依赖**：不需要 `npm install`，只依赖 Node 20+（本项目在 Node 24 上验证）。

```bash
node test/run.mjs    # 规则层 34 项
node test/e2e.mjs    # 浏览器层 22 项（需要本机 Edge/Chrome）
```

## 1. 规则层 `run.mjs`

把 `index.html` 里的 `<script>` 抽出来，在 Node `vm` 沙箱里用最小 DOM / Canvas / localStorage 桩运行（`harness.mjs`），通过 `window.__NEON` 直接驱动固定步长，不依赖浏览器。

擅长验证“数值与顺序”：连杀倍率读取时机、1.3s 无敌、0.95s 冲刺冷却、刷怪公式、补给时序、埋点属性、减少动效状态、12px 误触保护、四边生成分布等。

```js
const g = boot({ search: "?auto=1" });  // 可注入 query 与预置 localStorage
g.__NEON.start();
g.__NEON.tick(1 / 120);
```

## 2. 浏览器层 `e2e.mjs`

启动 headless Edge/Chrome，用原生 `fetch` + `WebSocket` 直连 CDP（Chromium DevTools Protocol），不引入 Playwright/Puppeteer。验证真实输入路径与真实布局：

- 真实鼠标点击（同意门、开始、重开）
- 真实键盘事件（`P` 暂停、`空格` 冲刺）
- 真实触摸事件（`Input.dispatchTouchEvent`：拖拽移动、点按冲刺/暂停、按钮边缘误触）
- 真实 `localStorage` 跨刷新持久化
- `Emulation.setDeviceMetricsOverride` 模拟 390×844 与 320×568
- `Page.captureScreenshot` 产出验收截图

> 浏览器进程需要创建 IPC 命名管道；在受限沙箱中会被拒绝（`0x5`），需在完整权限下运行。

## 已知文档矛盾与实现取舍

1. **连杀倍率**：表 5-6 写「第 1 杀 x1.1、第 40 杀 x5.0」，5.7 正文写「先加分再加连杀，因此第 1 杀 x1.0……第 41 只开始 x5.0」。按 5.7 的顺序实现（先读倍率、再累加），测试断言首杀 10 分、第 41 杀起 x5.0。附表 C 的「第 40 杀达到 x5.0」随之表现为第 41 杀。
2. **刷怪间隔公式**：PDF 表 5-8 把三个公式挤在一行，按表 5-5 的边界值（t=60 → 0.13s、倍率 1.33）反推为 `max(0.13, 1 - 0.016t)` 与 `min(2, 1 + 0.0055t)`，与实现一致。
3. **冲刺无敌**：文档称与受击无敌「两条独立计时、再叠加 0.26s」。实现用单计时器取 `max(inv, 0.26)`，与两条计时器的可见结果一致（任一存在即无敌）。
4. **埋点上报端**：V1.0 无后端，事件只进本地环形缓冲，预留 `window.__NEON_TRANSPORT` 钩子；因此「上报失败不阻塞」体现为不联网、不抛错。
5. **UI 热区**：按钮外框即热区（冲刺 64×64、暂停 48×48），视觉圆形/圆角矩形内缩 4px 得到 56px / 40px，符合 7.5 的视觉与热区双规格。
